# Async/await

`async/await` — это механизм, который позволяет **дождаться завершения операции и получить её результат**, не разрывая логику на колбэки и обработчики событий. Это делает код линейным и читаемым.

> Данная статья — небольшая практическая заметка для тех, кто только знакомится с `async/await` и `UniTask`.<br>
Цель — помочь быстро понять основные возможности `async/await` и научиться ими пользоваться, не углубляясь в то, как они устроены внутри. Но некоторые ключевые термины всё же придётся разобрать...


## Что такое асинхронный код?

Игровая логика часто требует дожидаться завершения длительного действия: задержки, нажатия кнопки, завершения анимации, ответа сервера.

То есть **асинхронная операция** — это операция, **завершение которой происходит не сразу**. При этом вызывающий код не обязан блокироваться и ждать её завершения.

**Колбэки и события** — распространённые способы организовать такую логику. Они позволяют продолжить выполнение после того, как произойдёт нужное событие или действие.

Но когда ожиданий становится много, логика может разноситься по разным методам и требовать флагов, обработчиков и ручного отслеживания состояния. С помощью `async/await` эту последовательность можно описать **в одном методе**.

> С `async/await` асинхронность остаётся той же, меняется только способ её описания!

## Пример

Для примера возьмём простой сценарий: нужно дождаться нажатия двух кнопок в любом порядке.

Подход с использованием событий обычно требует вручную отслеживать, какие события уже произошли:

```csharp
bool leftPressed;
bool rightPressed;

void Start()
{
    leftButton.onClick.AddListener(OnLeftButtonClicked);
    rightButton.onClick.AddListener(OnRightButtonClicked);
}

void OnLeftButtonClicked()
{
    leftPressed = true;
    CheckComplete();
}

void OnRightButtonClicked()
{
    rightPressed = true;
    CheckComplete();
}

void CheckComplete()
{
    if(leftPressed && rightPressed)
    {
        leftButton.onClick.RemoveListener(OnLeftButtonClicked);
        rightButton.onClick.RemoveListener(OnRightButtonClicked);

        Continue();
    }
}
```

> Здесь нет ничего принципиально плохого: код работает. Но приходится отдельно хранить состояние каждой кнопки, проверять его после каждого нажатия и не забывать отписываться от событий. 

С `UniTask` каждое нажатие можно представить как операцию, которая завершится в момент нажатия кнопки:

```csharp
async UniTask WaitForBothButtons()
{
    await UniTask.WhenAll(
        leftButton.OnClickAsync(),
        rightButton.OnClickAsync()
    );
    Continue();
}
```
Теперь сценарий читается почти как обычное описание задачи: дождаться нажатия левой и правой кнопки, а затем продолжить выполнение.

Главное отличие — **вся логика ожидания и продолжения находится в одном методе**, а не разнесена по обработчикам. При этом нам больше не нужно вручную хранить флаги и проверять, какая кнопка уже была нажата.

> `UniTask` — один из типов, представляющих асинхронную операцию. О нём мы ещё поговорим подробнее.

> `OnClickAsync` — метод расширения, который превращает нажатие кнопки в ожидаемую операцию. Внутри он подписывается на событие кнопки и завершает операцию после нажатия. <br>

## Два ключевых слова
Механизм основан на двух ключевых словах:

### await

**`await`** ставится **перед операцией, которую нужно дождаться**.<br>
После её завершения выполнение метода продолжится с этой строки.<br>
> Оно буквально означает: «Дождись завершения этой операции и продолжи выполнение метода».

### async

**`async`** **помечает метод как асинхронный и разрешает использовать `await`** в нём.<br>
Метод с `async` должен возвращать `Task`, `Task<T>`, `UniTask` или другой тип, который можно ждать (или void для обработчиков событий).


## Чего не делает async/await

- не ускоряет выполнение кода сам по себе;
- не создаёт новые потоки;
- не делает код параллельным.

Он делает **ожидание асинхронных операций удобнее** и позволяет не блокировать поток на время ожидания<br>
Поэтому `async/await` и многопоточность — разные вещи. Многопоточность позволяет выполнять работу на нескольких потоках, а `async/await` — описывать и ожидать завершение асинхронных операций.


<details>
<summary>Что происходит, когда ожидаемая задача выполняется в другом потоке?</summary>
await не заставляет текущий поток ждать завершения задачи и простаивать.<br>
Вместо этого выполнение метода приостанавливается, а поток освобождается для выполнения другой работы.<br>  
Когда задача завершится, выполнение метода будет продолжено с того места, где встретился `await`. При этом продолжение может произойти в том же или другом потоке — это зависит от используемого механизма и контекста выполнения.
</details>

## В контексте Unity
В игровой логике Unity часто приходится работать с операциями, которые завершаются не сразу: ждать нажатия кнопки, окончания анимации или эффекта, ответа сервера и многого другого.<br>

Часто такие ожидания нужно комбинировать — например, дождаться нескольких условий одновременно или выполнить несколько действий последовательно.

Именно здесь `async/await` оказывается особенно удобным. Вместо того чтобы разносить продолжение логики по разным методам, можно описать **весь сценарий в одном месте и в том порядке, в котором он должен выполняться**.

В результате последовательность действий становится проще читать и изменять: не нужно переходить между несколькими обработчиками, чтобы понять, что произойдёт дальше.
