# Руководство по репозиторию CatCodeGames (Agent & Contributor Guide)

Этот документ предназначен для разработчиков и AI-агентов, работающих с данным репозиторием. Здесь описано устройство проекта, правила вёрстки и оформления, а также пошаговый алгоритм добавления новых статей и разделов.

---

## 1. Архитектура проекта

Сайт построен на статическом генераторе **Jekyll** и хостится на **GitHub Pages**.
Проект намеренно не использует тяжёлые сторонние фреймворки и JavaScript-библиотеки: всё работает на чистом HTML, SCSS и возможностях Jekyll.

### Структура каталогов и ключевых файлов

```text
├── .docker/                   # Изолированная конфигурация для локального запуска
│   ├── compose.yaml           # Docker Compose сервис (порт 4000, livereload 35729)
│   ├── Dockerfile             # Сборка Ruby 3.3-slim + системные зависимости
│   ├── Gemfile, Gemfile.lock  # Зависимости Jekyll (изолированы от корня сайта)
│   └── _config.dev.yml        # Локальный конфиг (отправляет кэш Sass в /tmp/sass-cache)
├── _data/
│   └── topics.yml             # Реестр тем (разделов) сайта
├── _includes/
│   ├── breadcrumbs.html       # Хлебные крошки + микроразметка JSON-LD BreadcrumbList
│   └── site-footer.html       # Подвал сайта (дата сборки, копирайт, соцсети)
├── _layouts/
│   ├── default.html           # Базовый HTML-каркас (<head>, метатеги, подключение стилей)
│   ├── home.html              # Главная страница (шапка, интро, последние статьи тем)
│   ├── post.html              # Шаблон статьи (крошки, контент, навигация след./пред.)
│   └── topic.html             # Страница раздела (описание темы, полный список статей)
├── _sass/                     # Модульные SCSS-стили
│   ├── _tokens.scss           # Дизайн-токены (цвета, шрифты, размеры, брейкпоинты)
│   ├── _base.scss             # Базовые стили, сетка, типографика, таблицы, цитаты
│   ├── _components.scss       # Хлебные крошки, элементы списка статей (.post-item)
│   ├── _home.scss             # Стили главной страницы и блоков тем
│   ├── _post.scss             # Оформление текста статей, врезок aside, спойлеров details
│   ├── _syntax.scss           # Подсветка синтаксиса кода (Rouge) в тёмной теме
│   └── _about.scss            # Стили страницы «Об авторе»
├── assets/
│   └── main.scss              # Точка сборки CSS (импортирует все партиалы из _sass)
├── _unitask/                  # Коллекция статей раздела UniTask
├── unity/unitask/index.html   # Страница-хаб раздела UniTask (/unity/unitask/)
├── about/index.html           # Страница «Об авторе» (/about/)
├── 404.html                   # Страница ошибки 404
├── index.html                 # Главная страница сайта (/)
└── _config.yml                # Главный конфигурационный файл Jekyll
```

## 2. Локальный запуск (Docker)

Все файлы для работы через Docker вынесены в папку `.docker/`, чтобы не засорять корень репозитория лишними артефактами (`Gemfile`, кэш Sass, папка `_site` собирается во временный каталог контейнера).

**Запуск из корня проекта:**
```bash
docker compose -f .docker/compose.yaml up
```

## 3. Как добавить новую статью

### Шаг 1. Создать Markdown-файл

Статьи лежат в каталоге соответствующей коллекции (например, `_unitask/`).
Имя файла формируется по правилу: `NNN-kebab-case-slug.md`, где `NNN` — трёхзначный номер для удобной сортировки в проводнике (например, `013-custom-awaitable.md`, `120-cancellation-best-practices.md`).

### Шаг 2. Заполнить Front Matter

В начале файла обязательно указывается заголовочный блок YAML:

```yaml
---
layout: post
title: "Полный заголовок статьи: понятный и информативный"
short_title: "Короткий заголовок" # Для хлебных крошек и навигации (чтобы не перегружать интерфейс)
slug: custom-awaitable            # Используется в permalink коллекции
date: 2026-11-20                  # Дата публикации (ГГГГ-ММ-ДД), влияет на блок «Свежие заметки»
order: 13                         # Порядковый номер внутри темы (сортирует статьи в теме и навигации)
description: "Краткое описание (1-2 предложения) для превью, соцсетей и поисковой выдачи."
topic: unitask                    # Идентификатор темы из _data/topics.yml
# redirect_from: /old/path/       # Необязательно: если менялся адрес статьи
# last_modified_at: 2026-11-21   # Необязательно: дата обновления статьи
---
```

**Важные нюансы полей:**
* `order` — определяет логическую последовательность чтения. Именно по `order` работают кнопки «Предыдущая / Следующая» внизу статьи и порядок на странице темы `/unity/unitask/`.
* `date` — определяет, какие 3 статьи отобразятся на главной странице сайта (там выводятся самые свежие по дате).
* `short_title` — если не указан, везде будет использоваться длинный `title`. Рекомендуется заполнять, если полный заголовок длиннее 30–40 символов.

### Шаг 3. Правила оформления контента (Markdown & HTML)

1. **Главный заголовок:** Первый заголовок уровня `# Название` ставится в самом начале текста (он визуально встаёт сразу под хлебными крошками).
2. **Подзаголовки:** Используются только `##` (H2) и `###` (H3). Стили автоматически добавляют к ним стилизованные префиксы `## ` и `### `.
3. **Блоки цитат и пояснений:**
   * Стандартный `> Текст` — для важных выводов и акцентов (зелёная полоса слева, тёмная плашка).
   * Авторская реплика `> Текст {: .aside}` — для мыслей «на полях», примечаний и субъективных заметок (пунктирная серая линия, шрифт тише).
4. **Спойлеры / дополнительные детали:**
   ```html
   <details markdown="1">
   <summary>Краткий вопрос или тезис</summary>

   Подробный ответ или пояснение, которое можно скрыть, чтобы не перегружать основной текст.
   </details>
   ```
5. **Блоки кода:**
   * Всегда указывайте язык подсветки: ```` ```csharp ````.
   * Код форматируется с отступами в 4 пробела.
   * В C#-коде соблюдайте соглашения репозитория (префиксы `_fieldName`, лаконичные понятные имена).
6. **Внутренние ссылки:**
   Для ссылок на другие статьи блога используйте тег Jekyll:
   `[Название статьи]({% link _unitask/010-UniTaskCompletionSource.md %})`.
   Это защищает от битых ссылок при сборке.

## 4. Как добавить новый тематический раздел

Если вы создаёте новый раздел (например, по C# или шейдерам):

1. **Зарегистрировать коллекцию в `_config.yml`:**
   ```yaml
   collections:
     csharp:
       output: true
       permalink: /csharp/:slug/
   ```
   И в секции `defaults` убедиться, что тип размечен для SEO:
   ```yaml
   defaults:
     - scope:
         type: csharp
       values:
         seo:
           type: BlogPosting
   ```

2. **Добавить тему в `_data/topics.yml`:**
   ```yaml
   csharp:
     title: C#
     url: /csharp/
     parent: csharp
     description: Практические приёмы, тонкости языка и идиоматичный код.
     collection: csharp
   ```

3. **Создать страницу-хаб раздела (например, `csharp/index.html`):**
   ```html
   ---
   layout: topic
   topic: csharp
   title: C#
   description: "Заметки о возможностях современного C# и архитектурных паттернах."
   ---
   <p>Короткое введение в раздел: о чём эти заметки и для кого они.</p>
   ```

4. **Создать каталог коллекции:** `_csharp/` и добавлять туда статьи с `topic: csharp`.

## 5. Общие принципы стиля и кода сайта

* **Никакого визуального мусора:** Сайт выдержан в строгом, инженерно-минималистичном стиле. Акцентный зелёный `--color-accent` (`#4ade80`) используется точечно (стрелки, маркеры заголовков, фокус, выделение).
* **Семантика и доступность:** Все интерактивные элементы доступны с клавиатуры (`:focus-visible`), имеют семантичные HTML-теги (`<header>`, `<main>`, `<article>`, `<nav>`, `<time>`).
* **Мобильная адаптивность:** Сетка плавно перестраивается на мобильных экранах (`$breakpoint-mobile: 600px`).

* Сайт доступен по адресу: `http://localhost:4000`
* Настроен LiveReload (страница обновляется при сохранении файлов).

**Пересборка образа (если менялся `.docker/Gemfile`):**
```bash
docker compose -f .docker/compose.yaml up --build
```
